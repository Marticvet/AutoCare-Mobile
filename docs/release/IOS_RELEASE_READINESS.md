# iOS App Store release readiness

Last reviewed: 2026-11-07. This is a local configuration review only; no Apple, Expo, Supabase, PowerSync, or RevenueCat service was changed.

## First internal TestFlight build — prepared locally

- `eas.json` now has a separate `testflight` profile. It uses App Store distribution and remote EAS credentials, keeps the EAS environment selection at `preview`, and embeds the distinct runtime channel `EXPO_PUBLIC_APP_ENV=testflight`. It does not alter the existing `preview` or `production` policies.
- Apple and Google sign-in are enabled only for this explicit internal channel when all three non-secret flags in that profile are `true`. Preview and production continue to force both providers off. The existing PKCE callback, native Apple token path, email confirmation/recovery routes, and explicit identity linking are unchanged.
- The profile clears `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY`. If the selected iOS build environment has no real `appl_…` RevenueCat public SDK key, the app leaves RevenueCat unconfigured and hides purchase, restore, and subscription-management controls. This is deliberate for the first internal build; no Test Store key can be included.
- The polished opaque 1024 × 1024 sRGB app icon is at `assets/AutoCareIcon.png`, with the same image copied to `ios/AutoCareHub/Images.xcassets/AppIcon.appiconset/App-Icon-1024x1024@1x.png`. The prior icon is retained at `assets/AutoCareIcon-previous.png`; Android adaptive-icon assets were not changed.
- Google Maps initialization remains generated by the `withGoogleMapsIosInitialization` plugin before React Native can mount a `MapView`. The iOS API key is supplied through generated Expo config rather than a tracked Swift or plist literal. The appropriate EAS environment must supply the already-restricted iOS Maps key.

### Exact build handoff

1. In the selected EAS `preview` environment, confirm the non-secret Supabase/PowerSync configuration and the restricted iOS Google Maps key are present. Keep `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY` empty. Do not add a Test Store key or any server secret.
2. For this first billing-disabled internal build, leave `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` unset. When Apple products and the real RevenueCat iOS public SDK key are ready, set only that `appl_…` public key in the intended EAS environment and run separate StoreKit acceptance before enabling paid flows.
3. From a clean, supported Node 22/npm 10 checkout, run `npm ci`, `npm run release:check`, and `npm run release:doctor`.
4. Create the archive without submitting it: `eas build --platform ios --profile testflight`. This command builds an App Store-distribution artifact; it does not submit it to App Store Connect unless a separate submit action is requested.
5. Inspect the EAS build details and, only with separate approval, upload/submit the finished artifact using the chosen App Store Connect workflow. Do not use `eas submit` as part of this preparation.

## Fixed locally

- Distribution builds now fail during Expo config evaluation if either platform-specific RevenueCat key begins with `test_`. This prevents a Test Store key supplied through `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` from being embedded in a preview or App Store build. The pre-existing dedicated Test Store variable rejection remains in place.
- Supabase Auth is explicitly configured for PKCE. The Google browser flow accepts only an authorization code at `autocare://auth/callback`; token-bearing callbacks are rejected, and failed or expired code exchanges leave the current session unchanged with a localized retry error.
- First-time Apple names are persisted to Auth metadata and, only when the existing profile name is blank, to `profiles.full_name`, `first_name`, and `last_name`. The update is bound to the session's existing UUID and does not use a provider or private-relay email to merge accounts.

## Social authentication configuration — required, not applied

Preview and production force social providers off. For the current local iPhone Google-only acceptance, set `EXPO_PUBLIC_ENABLE_SOCIAL_AUTH=true`, `EXPO_PUBLIC_ENABLE_GOOGLE_AUTH=true`, and `EXPO_PUBLIC_ENABLE_APPLE_AUTH=false` only in the ignored local `.env`; then make a fresh signed development build. Do not add these values to preview or production EAS environments.

The Xcode **Run** action must use Debug. Native Release is intentionally mapped to `local-release`, which suppresses all providers. Debug Metro builds also use the current public development flags if an old embedded `EXConstants` manifest is cached by the Pods resource build phase.

If Google does not appear despite the local flags, stop any Metro process started with `expo run:ios --configuration Release`, then run `npx expo start --dev-client --clear` from this repository and relaunch the Debug app. Confirm the Login screen shows **Continue with Google** and no Apple control before beginning provider acceptance.
